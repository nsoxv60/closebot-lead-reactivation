# gohighlevel lead reactivation：如何把一堆“死线索”变成预约，而不是又发一轮没人回的群发短信

你账上那 3,000 个三个月没说过话的联系人，已经花过钱买进来了。做再多的 Facebook 广告，也买不到比“曾经主动填过表、问过价、留过手机号”更热的人。真正的问题不是名单，是回复之后那几分钟发生了什么。

大多数 GoHighLevel 数据库激活（database reactivation）失败的原因非常具体：他们做的是一次“发送”，而不是一次“对话”。工作流能发消息，但回答不了“多少钱”“能改成下周吗”“我上次那个报价还算数吗”。这些回复需要人接，量一大就没人接得住，然后整批线索再次沉睡。

下面是把这件事做对的具体做法，以及一个专门用来填这个“回复缺口”的工具——CloseBot——现在真实的套餐和价格。

## 先看清楚你的名单里到底有谁

决定激活效果的不是文案，是排除名单。一个运营两三年的 sub-account 通常有 5,000 到 40,000 个联系人，其中真正可以重新触达的可能只有三分之一。

先建一个保存好的 Smart List，不要导 CSV。基础筛选条件大致是：

- 创建时间超过 90 天
- 过去 60 天没有任何 inbound message
- 过去 90 天没有预约
- 手机号是 E.164 格式

最后一条经常被忽略。号码如果存成 `0412 345 678` 这种本地格式而不是 `+61412345678`，短信会静默失败，你只会看到回复率忽然变成 0，然后误以为是文案问题。

排除项不是可选项：任何渠道上开了 DND、退订过邮件的人；有 open Opportunity、有未来预约、还是活跃客户的人；员工、供应商和测试记录；硬退信邮箱、把座机填进手机字段的条目。

活下来的那批人，用一个明确的 tag 标记，比如 `dbr-2026-09-batch1`。用 tag 而不是自定义字段，因为工作流触发器和 Smart List 都按 tag 干净地过滤，活动结束后批量移除也方便。

## 激活活动真正死在哪一步

这里有个很有说服力的数字。CloseBot 自己拿 1,486 个旧账号跑过一次激活，9 天里 602 人回复——但他们发现，**最终会回复的人里只有 38% 是回了第一条消息的**。平均要两条消息才换来一次回复。换句话说，如果你只发一条短信就收手，你主动放弃了超过一半本来会回应的人。

第二个数字更能说明问题。一个叫 Ari 的 agency 老板给一家母女美容院做激活，3,000 个沉睡联系人，先用传统方式跑：定时短信群发加人工看回复，结果是 3 个预约，而且每一个都要他手动去约。同一个名单，换成对话式 AI 接管回复，**两天 36 个预约**，后来又陆续加进来一些。按约 200 美元的平均客单价，大约 7,000 美元的收入。

需要说清楚的是：第一轮失败的不是 GoHighLevel 的 AI，因为第一轮里根本没有 AI。那是定时消息加一个真人。十倍差距来自把一段“定时消息”换成了“一段真正的对话”——AI 能回答、能处理异议、能在客户说“等假期之后再说”之后三周重新接上那根线，而群发短信做不到这一点，所以对方根本不回。

> 活动真正的产出不是短信，是回复。回复超过十分钟没人接，预约率基本砍半。

## 在 GoHighLevel 里搭这条工作流

把它做成**一个** Workflow，不是五个。一个工作流配好 goal event，比一串 campaign 好调试得多。

**触发器**：Contact Tag — tag added — `dbr-2026-09-batch1`，关闭 re-entry。然后分批给 Smart List 批量打标签，不要一次塞进去 5,000 个人。

**节奏**：Drip 每天 50 到 500 条，Wait step 限定工作日 9:00–18:00，并且按联系人所在时区判断。最后加一个“每条间隔 2 分钟”的 drip。第一次跑就全量发送，会在周二早上把你自己的发送号打爆，也把回复量堆到没人处理。

**第一条消息**：只问一个问题，不报价、不发日历链接。


Hi {{contact.first_name}}, it's Sarah from Northside Dental. You enquired a while back about a check-up and clean and we never got you booked in. Are you still after one? Reply STOP to opt out.


**Goal event**：设为 Customer Replied，放在能捕捉任意位置回复的地方。goal 分支里要做五件事：移除活动 tag、加 `dbr-replied`、创建 Opportunity、把对话分配给某个用户、以及**显式地把联系人移出工作流**。最后一个动作最常被漏掉，结果就是已经回复“好，打给我”的人，第四天还在收第三条催单短信。

**Opportunity 阶段**：给激活单独建一个 pipeline，别污染客户的主销售管道。阶段用 Attempting Contact → Engaged → Booked → Attended → Won → Lost，来源标成 Database Reactivation。客户能一眼看到这个活动产出了什么，而不是你把一个数字口头报给他。

到这一步，剩下的就是那个绕不开的问题：谁来回消息。

## 先把合规和送达率这两件“无聊事”做掉

这部分没人爱看，但它决定你的域名和号码下周还能不能用。

发送方必须是可回复的号码，不能用 alphanumeric sender ID，因为那种 ID 收不到回复，等于退订功能和整个活动的意义同时失效。每条短信都要带业务名称和一个零成本的退订方式，`Reply STOP` 是标准做法。退订请求必须及时处理。

分批发送，单批 300–500 条，看着回复量和 STOP 率再放下一批。STOP 率一旦超过大约 3%，说明名单或文案有问题，停下来而不是硬发完。

激活名单只触达能给出生来源的人。如果客户说不清某个联系人是从哪来的，那就排除掉——尤其别碰买来的名单。

## 这篇东西到底适合谁

如果你的数据库里有几百到几万个 90 天以上没互动的联系人，而且已经在用 GoHighLevel，那这条路径的性价比很难被别的动作超过。名单已经付过钱，激活活动几乎没有新增获客成本，主要投入是构建时间和回复处理。

反过来说，如果你的名单只有几十个人，打电话更快，也更体面。如果团队无法在客户回复后十分钟内响应，也别急着跑 5,000 人的批次——先把回复兜底方案想清楚，无论是加人还是加 AI。

最后一点判断：别把激活当成一次性活动。跑完一轮，把回复过、预约过、到场过的人分别打上 tag，三个月后再针对不同分组跑第二轮，转化率通常会比第一轮更好，因为那时候你已经知道谁会对什么话有反应。
